# qq-agent-browser —— 浏览器（Edge 调试端口）

让机器人**真的能开网页**：把页面在一个真实浏览器里打开、等 JS 渲染完，再取正文 / HTML / 无障碍树，或者直接**截图发到群里**。

## 为什么需要它

核心自带的 `web_fetch` 抓的是静态 HTML。现在的站点大多靠 JS 渲染 —— 抓回来经常只剩一个空壳（实测：B 站视频页纯 HTTP 只拿到一行 `<title>`）。这个插件走本机 Edge 的调试端口（CDP），页面是**真的被打开**的，取到的是渲染后的结果。

## 能做什么

| 动作 | 说明 |
|---|---|
| `tabs` / `url` | 看有哪些标签页、当前页是什么 |
| `open` / `newtab` | 打开网址（`open` 用当前标签，`newtab` 开新的）|
| `text` / `html` | 取页面可见文本 / HTML（渲染之后的）|
| `a11y` | 无障碍树（角色 + 名称，比 HTML 干净）|
| `eval` | 在页面里跑一段 JS（支持 await）—— 滚动加载、翻页、读数据都靠它 |
| `click` / `fill` | 点元素 / 填输入框 |
| `shot` | 截图。传 `send: true` 就**直接发到当前会话**（群友能看到）；`fullPage: true` 截整页 |
| `wait` | 等选择器出现、或等某个 JS 表达式为真（SPA 的数据常在 `readyState=complete` 之后才注入）|

典型用法（模型自己组合）：

- **看 JS 渲染的页面**：`open` → `wait`（等关键元素）→ `text` 或 `a11y`
- **群友想看某页长什么样**：`open` → `shot` + `send: true`
- **看视频画面**：`open` 视频页 → `eval` 设 `document.querySelector('video').currentTime = 30` → 等一会儿 → `shot`（只能拿画面，拿不到声音）

## 安全模型（三条都是刻意的）

1. **独立 profile**：默认用 `data/qq-agent-browser/profile` 起浏览器，与你平时那个浏览器**完全隔离**。
   群友就算使唤机器人开网页、截图，也读不到你的任何登录态。⚠️ **别**把这里改成你日常那个
   `user-data-dir` —— 那等于把全部账号交给机器人。
2. **会话白名单**：默认只有核心白名单里的群 / 好友能触发（和"机器人能不能回话"是同一份名单）。
3. **动作白名单**：`eval` / `click` / `fill` 这类"能操作页面"的动作可以在设置里去掉，
   最保守就填 `tabs,url,open,text,html,shot,wait`。

## ⚠️ 端口要避开 9222

默认端口是 **9333**。这不是随便选的：**9222 上通常挂着别的浏览器实例**（你平时那个、或别的工具起的带调试端口的那个），而插件只要发现端口在听就会**直接连上去用** —— 端口撞车 = 把那个实例里的登录态交给机器人。

CDP 的 `/json/version` 不返回 profile 信息，所以这条只能在端口这一层隔离。**要改端口，就改成一个只有本插件在用的**。

## 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | 开 | 关掉后工具直接消失 |
| `port` | `9333` | 调试端口，见上面那条警告 |
| `profileDir` | 空 | 留空 = 用插件自己的 `data/qq-agent-browser/profile`（推荐）|
| `edgePath` | 空 | 留空 = 自动在常见安装位置找 Edge/Chrome |
| `actions` | 全部 | 允许的动作，逗号分隔 |
| `autoLaunch` | 开 | 端口不通时自己把浏览器拉起来（用上面的独立 profile）|
| `sendShotToChat` | 开 | 允许模型把截图发到当前会话 |
| `onlyWhitelist` | 开 | 只有白名单会话能用 |
| `domainAllow` | 空 | 填了则 `open`/`newtab` 只放行这些域名（如 `bilibili.com, zhihu.com`）|

## 常见问题

- **`WebSocket is not defined`** —— 宿主 Electron 内置的 Node 20 **没有**全局 `WebSocket`（Node 22+ 才有）。
  插件已经做了「全局优先、`ws` 包兜底」，而 QQ Agent 的 `package.json` 自带 `ws` 依赖，所以开箱可用；
  真看到这条错误，说明两个都拿不到，检查宿主的 `node_modules/ws` 是否还在。
  这个坑的形态很好认：**浏览器明明起来了（端口在听、窗口都在），但每次操作都报错**。
- **`浏览器没就绪：调试端口 xxx 没在监听`** —— 自动启动被关了，或浏览器起不来。工具返回里会给一条可直接复制的启动命令。
- **`找不到 Edge/Chrome 的可执行文件`** —— 在设置里填 `edgePath`。
- **截图发不出去** —— 图太大（QQ 有限制）或 `sendShotToChat` 被关了；返回里会写原因。
- **页面看到登录墙** —— 正常。独立 profile 里没有你的登录态，这是刻意的，**不要**去填账号密码。

## 和 web_fetch / web_search 的分工

公开的、静态的、结构化的内容 → 先用 `web_fetch` / `web_search`（快得多）。
只有当"抓回来是空壳 / 乱码 / 只有标题""要靠 JS 渲染""要点一下翻一页"时，才轮到它。

## 上传到市场前的检查

本插件目录里**不含任何个人数据**：端口、profile 路径、白名单全部走 `api.config()`，存在 `data/config.json` 那棵树里，**不在插件目录**。所以点「上传到市场」是安全的。

打包范围是**整个插件目录**（`market.js` 不做任何排除），所以上传前请顺手确认目录里没多出：
`*.log`、`.env`、你自己改过的 `plugin.json`（尤其是 `settings` 里填了真实路径/域名的那些）。

## 更新记录

### v1.1.1（2026-10-10）

- **清单简介里补了用法示例**（市场页 / 技能页显示的那段）：直接丢一个链接说「打开这个网页截个图」就行。

### v1.1.0（2026-10-10）—— 一轮代码审查后的修复

| 修复 | 说明 |
|---|---|
| `text` / `html` 加了默认上限 | 之前不传 `maxChars` 就**完全不截断**，一个大页面能把几十万字符塞进模型上下文（宿主对工具结果不做二次截断）。现在默认 8000 字符、上限 50000，可用 `maxChars` 调 |
| `a11y` 默认可用 | 清单里的默认动作列表漏了 `a11y`，而工具描述、本文档、设置说明都在公布它 —— 模型一调就被自己拒绝 |
| 显式 `tab: 0` 不再被忽略 | 判「有没有给 tab」用了 falsy，而 `0` 是合法索引：模型明确要看第 0 个标签页时，会静默读到别的页 |
| 默认标签按会话隔离 | 之前所有群共用一份「我打开的标签」：多群时群 B 可能截到群 A 的页面并发进群 B，并发会话之间也会互相覆盖 |
| 白名单补上黑名单判定 | 之前只看 `allow`、漏了 `deny`，与核心「能不能回话」的口径不一致（核心是 deny 优先） |
| 关掉 `enabled` 后工具真的消失 | 之前 `available()` 不看自身开关：模型仍看得见、仍会调用，只是每次都被拒一句 |
| 启动失败不再堆进程 | 15 秒没就绪时回收自己拉起的浏览器，并加 60 秒退避；之前每次调用都会再 spawn 一个 |
| 截图先落盘再发 | 绕开宿主的图片去重键（同尺寸截图前 64 字符相同，8 秒内第二张会被当成「刚发过」），顺带省掉 base64 的 1/3 体积放大 |
| 其它 | `fill` 支持 `select` / `contenteditable`；`fullPage` 接受 `"true"` / `1`；纯字母的标签 id 不再被自家校验拒绝；连不上时不再让你去跑一个本插件没有的 `start-edge.ps1`；工具分类改到宿主认识的 `web`（否则设置页不渲染它的开关卡片）|

新增参数：`maxChars`（text/html 的返回上限）、`maxNodes`（a11y 节点数）、`frame`（进跨域 iframe 取内容）。

> 分类说明：`plugin.json` 顶层的 `category` 是**市场分类**（市场有 utility 这一类），
> 而工具定义里的 `category` 是**宿主工具分类**（只有 messaging/sticker/query/memory/web/knowledge/media/system 八类）。
> 两边不是一个体系，所以本插件的工具用 `web`、清单仍用 `utility`。
