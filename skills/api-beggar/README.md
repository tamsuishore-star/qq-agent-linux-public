# API 余额告急乞讨（api-beggar）

查 API 中转站的余额，**低于阈值时让模型用自己的人设在群里求一句充值**。带冷却和缓存，不会刷屏。

**v1.1.0 改成关键词触发**：群里说到「查余额」这类词才查（钩子硬匹配），平时**零额外成本**；
另外会在核心的「主动机会」里巡查一次，低了才喊。不再是旧版那种"每轮必调一次工具"的烧钱写法。

## 三步配置

1. 控制台 →「技能」→ `API 余额告急乞讨` → 设置
2. 填 **API Base URL**（例如 `https://api.example.com`）+ **查询用 API Key**，**演练模式保持开启**，保存
3. 群里说一句 **「查余额」** → 看会话卡片里工具返回的 `status` 和余额数字对不对；

   - 接口或字段不对 → 按下面「余额接口对不上」调 `余额接口` / `余额字段` / `单位换算除数`
   - 数字对了 → 关掉**演练模式**，正式启用

> 演练模式开着时**也会真查余额**（你能看到数字），只是不会让模型为此发言。所以先配通、再放开。

## 设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| API Base URL | 空 | 中转站根地址，不带结尾斜杠 |
| 余额接口 | 空 | 空 = 自动探测（DeepSeek / new-api / one-api 等 4 个候选）；可填完整 URL 或 `/xxx` 路径 |
| 余额字段（点路径） | 空 | 例如 `data.balance`、`balance_infos.0.total_balance`；空 = 自动找 |
| 单位换算除数 | 1 | 返回的是额度整数时才改（如 `500000` = 1 元） |
| 查询用 API Key | 空 | 🔒 密码框，**留空 = 不修改** |
| **乞讨阈值** | **5** | 余额低于它就求充值 |
| **冷却（分钟）** | **120** | 两次求充值的最小间隔，填 0 = 不冷却 |
| **余额缓存秒数** | **300** | 多久内不重复请求接口，填 0 = 每次实时查 |
| 演练模式 | 开 | 开着 = 只报告不发言 |
| **触发关键词** | `查余额,余额,还剩多少,够不够,钱够吗,没钱了,要充值,快没钱,余额不足` | 本轮消息里出现才查；留空 = 恢复默认词表 |
| **触发范围** | `keyword+proactive` | `keyword` = 只认关键词；`keyword+proactive` = 关键词 + 主动机会也巡查一次 |

改完**保存即生效**（技能每次执行时现读设置），不用重启。

## 为什么这样省 token

旧版（v1.0.0）在提示词里写"每次开始回复前调用一次"，代价是**每轮 1 次工具往返 + 每轮 150~200 token
固定片段** —— 往返才是大头。v1.1.0 删掉静态片段，改成钩子命中才注入：

| 场景 | v1.0.0 | v1.1.0 |
|---|---|---|
| 普通群聊回复 | 1 次往返 + 固定片段 | **0 往返、0 片段**（只剩瘦身后的工具描述，属缓存前缀） |
| 有人问余额 | 1 次往返 | 1 次往返（躲不掉，见下） |
| 主动机会 | 1 次往返 | 1 次往返，且有缓存 300s + 冷却 120min 兜底 |

**为什么命中后还是要 1 次工具往返**：钩子按约定**禁网禁发**（plugin-development.md §3.2），
做不到"钩子里查完把余额塞进提示词" —— 查余额只能是会话内的一次工具调用，这是下限。
同理**工具描述无法按关键词隐藏**（核心按 `skillContext` 过滤工具，而 `skillContext` 里没有消息文本，
见 `orchestrator.js:762-770`、`889-899`），所以它每轮都在，只是被瘦身到约 1/3。

## 工具返回的五种状态

工具返回文本的**第一行永远是 `status: xxx`**，钩子注入的【触发】指令据此决定模型的动作：

| status | 含义 | 模型会做什么 |
|---|---|---|
| `ok` | 余额 ≥ 阈值 | 绝口不提钱；顺便清掉冷却 |
| `low` | 余额 < 阈值 | **发一条求充值的消息**（一条就够，说完收尾） |
| `cooling` | 低于阈值但冷却没过 | 当无事发生 |
| `not-configured` | 没填接口地址 | 不进群，只留在会话记录里 |
| `error` | 查询失败 | 最多再试一次，不进群 |

**冷却先记再说话**：返回 `low` 之前就写好冷却时间，所以同一次会话里模型不会连喊三次。
**充上钱自动解锁**：余额回到阈值以上时冷却被清零，下次再跌可以立刻喊。

## 余额接口对不上怎么办

自动探测按这个顺序（命中即停，命中的地址会被记住）：

| 顺序 | 路径 | 常见站点 | 取值路径 |
|---|---|---|---|
| 1 | `/user/balance` | **DeepSeek 官方** | `balance_infos.0.total_balance`（数组 + 字符串金额 `"110.00"`） |
| 2 | `/v1/dashboard/balance` | new-api 及多数中转站 | `data.balance` |
| 3 | `/api/user/self` | 老 one-api | `data.quota`（额度单位，配 `单位换算除数=500000`） |
| 4 | `/v1/account/balance` | 部分自建网关 | `data.balance` |

### DeepSeek 官方（已实测）

```
API Base URL     https://api.deepseek.com     ← 结尾不带 /v1
余额接口         /user/balance                ← 留空也能探测到
余额字段         balance_infos.0.total_balance ← 留空也能自动找到
单位换算除数     1                             ← CNY 按"元"返回
```

已验证：`GET https://api.deepseek.com/user/balance` 不带 Key 返回 **401**（路径存在），
带 Key 返回 `{"is_available":true,"balance_infos":[{"currency":"CNY","total_balance":"110.00",...}]}`。
⚠️ 海外账号 `currency` 是 `USD`，此时阈值 `5` 语义是"5 美元"，想按人民币判断请相应调阈值。

四个都不中 → 手动填**余额接口**（完整 URL 或 `/path`）+ **余额字段**（点路径）。
返回里有数但显示的不对 → 八成是单位问题，填**单位换算除数**。

状态文件写在应用数据目录（安装目录 `data\skill-api-beggar-state.json`，记录冷却时间和上次命中的接口）。
**它不在技能目录里**，所以不会触发热重载 —— 热重载监听的是 `skills/` 整棵目录，
自己往里写文件会造成"写文件 → 重载 → 内存状态清零"的自激回路。

## 触发时机（v1.1.0 关键词硬触发）

触发由 `index.js` 导出的 **`before-llm-messages` 钩子**判定，**不依赖模型自觉**：

1. **关键词**：只在 `【未读信息】` 那一段里匹配（= 本轮触发消息），切到下一个核心段标题截止 ——
   所以"10 条之前有人聊过余额"**不会**误触发。命中才往消息末尾追加一行 `【触发】…` 指令，
   不命中**什么都不注入、零成本**；注入是追加在末尾，系统提示和用户提示前缀一个字节没动，**不破坏前缀缓存**。
2. **主动机会**（`触发范围 = keyword+proactive` 时）：proactive 轮注入巡查指令 ——
   `ok` 就安静结束、`low` 才喊一条，频率由缓存 300s + 冷却 120min 兜底。

但技能要干活，得先有一个会话，会话的来源只有两个：

1. 群里有人说话（受设置里「响应档位滑条」控制）
2. 核心的**主动机会**：设置 → proactive（默认概率 0.25、间隔 30~90 分钟、群里冷场才触发）

**兜底**：钩子万一被 5s 超时或异常吞掉（manager 会隔离，只记日志），模型仍看得到工具描述，
可以自己决定调用 —— 不会因此功能失效。

⚠️ 注入依赖核心的 `【未读信息】` 段标题（`prompt.js:855`）。若未来核心改了这个标记，
钩子切不出触发段 → **静默不注入**（方向是安全的：不触发 = 不花钱）。

## 排障

| 现象 | 原因 / 处理 |
|---|---|
| 模型完全不调用这个工具 | 技能被禁用了 —— 看控制台「技能」页的可用性原因 |
| 说了「查余额」没反应 | 关键词没对上 → 改**触发关键词**；或模型没理会注入（看会话卡片里有没有工具调用，再喊一次） |
| 没人问也在查余额 | `触发范围 = keyword+proactive` 时**主动机会**那轮查是正常的；普通闲聊也查 → **触发关键词**设得太宽（别用单字，如「钱」） |
| 注入似乎没生效 | 钩子超时/报错（日志有「触发判定失败」）→ 模型凭工具描述兜底调用；或核心改了 `【未读信息】` 标记 |
| `status: not-configured` | 没填 API Base URL |
| 报「连不上余额接口」 | 地址写错、需要代理、或站点只允许面板访问 |
| 报「余额接口返回了错误」 | HTTP 4xx/5xx —— Key 不对、或这个接口路径不适用（换个探测候选） |
| 报「返回格式对不上」 | 返回不是 JSON，或字段路径不对 → 填**余额字段** |
| 余额数字是天文数字 | 单位问题 → 填**单位换算除数**（one-api 系常见 500000） |
| 一直 `cooling` | 冷却还没到点，或时间不准；想立刻再测把**冷却**临时设 0 |
| 从来没在群里说过 | 演练模式还开着 / 阈值高于当前余额 / 没有会话触发（见上「触发时机」） |
| 报「本技能没有联网权限」 | `skill.json` 的 `permissions` 被改坏了，应为 `["web_fetch"]` |
